# STATIC-NODE-001 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement the smallest executable parent → isolated child → receipt → optional Workmark → HOLD loop without granting child promotion authority.

**Architecture:** Add a pure TypeScript kernel for deterministic attempt receipts, Workmark derivation, result/disposition rules, and validation. Add one opt-in local process adapter that creates a Git worktree from an exact clean parent HEAD, runs exactly one declared build command and one declared verification command inside the child, measures the delta, emits the kernel bundle, and stops at HOLD. The runner must never mutate or promote the parent.

**Tech Stack:** TypeScript 5.8, Node.js 24, existing `addressJson()` / `sha256()` identity helpers, Node test runner, Git CLI via `child_process`.

**Spec:** `docs/superpowers/specs/2026-09-16-static-node-001-design.md`

## Global Constraints

- The running node may build its successor, but may not declare its successor.
- `PARENT != CHILD`; `CHILD != COPY`.
- `BUILD SUCCESS != VERIFICATION SUCCESS`; `VERIFICATION SUCCESS != PROMOTION`.
- Every completed attempt ends with `disposition: "HOLD"` and `promotionAuthorized: false`.
- Workmarks are emitted only for verified children.
- Failed attempts remain attributable receipt evidence.
- Reuse existing `addressJson()` and `sha256()`; add no new canonical-addressing scheme.
- No merge, rebase, cherry-pick, push, tag, release, deploy, restart, daemon, scheduler, autonomous task selection, retry/repair loop, or Dogram dependency.
- The runner executes only explicit operator-supplied command strings and is not a sandbox.
- The parent checkout must begin clean and remain unchanged.
